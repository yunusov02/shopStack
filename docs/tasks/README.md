# Task breakdown

The roadmap (`docs/retail-saas-roadmap.md`) is the source of truth. These files break every roadmap item into small tasks: one task is one piece of work that fits in one PR (a model, a migration, a repository, a service, a set of endpoints, a test file, an ADR).

## Format

```
- [ ] **S3.T07** One concrete piece of work, stated so you know when it is done
  Must know: the things you must be familiar with before starting
```

- `S<stage>.T<number>`: stage 3, task 7. Tasks inside a stage are in dependency order: do them top to bottom.
- `Must know` names concepts, libraries or tools. If one is new to you, read about it first (official docs), then start the task.
- Tags `[CORE]`, `[EXT]`, `[OPT]` are inherited from the roadmap item above the task group. Finish every `[CORE]` group of a stage before `[EXT]`.
- Each module repeats the same sequence: model → migration → repository → service → schemas → endpoints → tests. Tests are a separate task on purpose, so a PR without tests is visibly incomplete.
- Tick the box when the task's PR is merged with green CI. When every task of a roadmap item is ticked, tick the roadmap item.

## Files

| File | Roadmap |
|---|---|
| `stage-00-setup.md` … `stage-10-scale.md` | Levels 1–2, fine-grained |
| `stage-11-hr.md` … `stage-25-marketplace-sync.md` | Levels 3–5, one task per module piece |
| `stage-26-general-ledger.md` … `stage-33-multi-company.md` | Part II (ERP), one task per module piece |
| `stage-34-data-platform.md` … `stage-41-llm-assistant.md` | Part III (data and ML platform), one task per pipeline, model or service piece |
| `theory-tracks.md` | Theory tracks, one task per topic |

## Conventions used in tasks

- "model" = SQLAlchemy model in `modules/<name>/models.py`, with `tenant_id` where the roadmap requires it.
- "migration" = Alembic revision, autogenerated then reviewed by hand.
- "repository" = data access only, no business rules.
- "service" = business rules, works through the Unit of Work, raises domain errors.
- "endpoints" = FastAPI router with Pydantic v2 schemas, permission dependency, single error format.
- "tests" = pytest + pytest-asyncio + httpx against a real Postgres (Testcontainers from S0.T16).
- Part III additions: "DAG" = an Airflow DAG in `data/dags/` that only imports from `data/`; "dbt model" = a model in `data/warehouse/models/` with tests; "job" = a PySpark job in `data/jobs/`; "pipeline" = a training or scoring script in `ml/pipelines/` run from a DAG; "lab" = a measured experiment whose numbers go into the README; every model task ends with a comparison against its baseline.
